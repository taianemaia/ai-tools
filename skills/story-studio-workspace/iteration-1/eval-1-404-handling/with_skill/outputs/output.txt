Story: As a shopper, I want the Product Detail Page (PDP) to return a 404 response when the requested product is unavailable, so that I receive a clear not-found experience instead of a broken or empty page.

Acceptance Criteria:
- The PDP route returns an HTTP 404 status code when the SKU does not exist in the catalog (including deleted and archived SKUs).
- The PDP route returns an HTTP 404 status code when the SKU belongs to an unpublished product.
- The PDP route returns an HTTP 404 status code when the SKU is out-of-market for the locale derived from the URL locale segment of the request.
- When no locale segment is present in the URL, the request is treated as out-of-market and a 404 is returned.
- A user-facing 404 error page is rendered in all cases above.
- No redirect (301/302) is issued for any of these conditions — a 404 is returned directly.
- Valid, published, in-market product URLs continue to resolve and render the PDP without any change in behavior.

INVEST Note: The story is independent, negotiable, valuable, estimable, small, and fully testable; all four 404 conditions are explicitly defined with unambiguous scope and a clear locale source.

Story Points: 3 — moderate complexity across four distinct conditions and locale-aware routing logic, with well-defined scope reducing implementation risk.
