[STORY WRITER - turn 1]

CLARIFY:
1. What are the AEM rules for when a product (PDP) should return a 404? For example, under what conditions is a product considered "not found" (invalid SKU, unpublished, out-of-market, etc.)?


[NEEDS INPUT]
The Story Writer needs the following clarification before writing the story:

1. What are the AEM rules for when a product (PDP) should return a 404? For example, under what conditions is a product considered "not found" (invalid SKU, unpublished, out-of-market, etc.)?

User answer: A product is 404'd if the SKU is invalid, unpublished, or out-of-market for the user's locale.


[STORY WRITER - turn 1]

STORY:
Story: As a shopper, I want invalid product pages to return a 404, so that I am not served a broken or irrelevant product page.

Acceptance Criteria:
- The system returns a 404 response when the requested product SKU is invalid.
- The system returns a 404 response when the requested product is unpublished.
- The system returns a 404 response when the requested product is out-of-market for the user's locale.
- For all other non-404 scenarios, existing PDP behaviour remains unchanged.

INVEST Note: The story is independent, testable with three explicit conditions, valuable to end users, and small enough to complete in one sprint.

Story Points: 3 — Three well-defined conditions with confirmed rules; effort is moderate due to locale-aware lookup, though the locale resolution approach is still to be confirmed.

Open Questions:
- Locale resolution mechanism — the stakeholder confirmed that out-of-market products for the user's locale should 404; the mechanism for determining the user's locale (e.g., header, cookie, session, existing locale service) has not been specified.


[TECH LEAD - turn 1]

NEEDS_REVISION:
- The criterion "out-of-market for the user's locale" does not specify how the user's locale is determined (e.g., from a request header, a cookie, a session value, or an existing locale service). Add a criterion or note clarifying the locale resolution mechanism, or surface it as an Open Question if it is unknown.
- The persona "developer" is atypical for a user story — the value statement points to an end-user benefit. Consider whether the persona should be "user" or "shopper", or justify the developer persona if this is purely a technical story.
